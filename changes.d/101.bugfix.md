`xdiff dirs` now pairs each file with at most one file in the other directory, so a recursive `--filter` such as `"**/*.nc"` no longer compares a file with every file of the same name. A file in a subdirectory that the comparison directory lacks used to be paired with a same-named file elsewhere, and the run could pass (#47).
- Files pair by relative path first. The files left over then pair by file name, then by `--common-pattern`, and only when exactly one leftover file on each side has that name or match.
- When a name or `--common-pattern` match is shared by more than one leftover file in either directory, none of those files is paired: each fails as `AMBIGUOUS`, naming the files on the other side. Narrow the run with `--filter` or make `--common-pattern` more specific (for example `"\d{8}_grid_[TU]"` instead of `"\d{8}"` when each date has a `grid_T` and a `grid_U` file).
- With the default `--filter "*.nc"`, which does not look into subdirectories, pairing is unchanged.
