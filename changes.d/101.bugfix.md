`xdiff dirs` now pairs each file with at most one file in the other directory, so a recursive `--filter` such as `"**/*.nc"` no longer compares a file with every file of the same name. A reference `sub/x.nc` that the comparison directory lacks used to be paired with the comparison `x.nc`, which already had its own pair, and the run could pass (#47).
- Files pair in three steps: by relative path, then by file name, then by `--common-pattern`. Each step looks only at the files that no earlier step paired or reported, and pairs files sharing a name or match when there is exactly one on each side.
- When there are more on either side, none of those files is paired: each fails as `AMBIGUOUS`, naming the files on the other side. Narrow the run with `--filter` or make `--common-pattern` more specific (for example `"\d{8}_grid_[TU]"` instead of `"\d{8}"` when each date has a `grid_T` and a `grid_U` file).
- `--common-pattern` no longer adds pairs for files that already pair by relative path or file name: with `"\d{8}"`, a `grid_T` file is no longer also compared with the `grid_U` file of the same date.
- With the default `--filter "*.nc"`, which does not look into subdirectories, and no `--common-pattern`, pairing is unchanged.
